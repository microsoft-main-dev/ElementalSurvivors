# Иконки интерфейса

Исходники PNG. В игру они попадают не отсюда: Roblox работает только
с загруженными ассетами, поэтому файлы заливаются в Roblox, а в код идут
их числовые Asset ID — все в одном месте, `src/Shared/Config/Icons.luau`.

Картинки нарисованы владельцем (правило 4 ТЗ: сторонних ассетов в проекте нет).

**Ноль в `Config/Icons` означает «ассета нет»** — панель тогда рисует прежнюю
заглушку, а не пустое место. Игра полностью работоспособна с одними нулями,
и остаётся такой, если ассет когда-нибудь снимет модерация.

`thorn_cone`, `static_orbit`, `shadow_chain`, `void_nova`, `holy_aura`,
`radiant_bolt`). Они не мусор: появится способность такой стихии и формы —
картинка уже есть.

## Требования к файлам

- PNG с альфа-каналом. Квадрат 256×256 для мелких иконок, 512×512 для магазина;
  баннеры локаций — 512×224.
- Объект по центру с полем по краям: иконки рисуются со скруглением,
  и то, что упирается в край, срежется.
- Без текста внутри картинки. Название и цена рисуются подписью рядом.

## Кольца и рамки

**У питомцев рамки в файле быть не должно.** Кольцо вокруг иконки питомца
рисует `Client/UI/PetIcon` цветом РЕДКОСТИ из `Palette.Rarity` — это
единственный способ отличить B от SSS с одного взгляда. Своя рамка в файле
даст второе кольцо, которое про нашу шкалу редкостей ничего не знает.

У способностей, снаряжения и расходников наоборот: там плитка вшита в картинку,
и код свою подложку гасит.

## Нарезка растягиваемых кусков

Всё из `skin/` рисуется девятью кусками (`ScaleType = Slice`): углы остаются
как есть, середина тянется. Углы измерены по самим файлам — радиус скругления
плюс запас:

| Файлы | Размер | `SliceCenter` |
|---|---|---|
| `frame_window` | 64×64 | `Rect.new(14, 14, 50, 50)` |
| `frame_row`, `frame_slot`, `button_*`, `tab_*` | 48×48 | `Rect.new(12, 12, 36, 36)` |
| `bar_background`, `bar_fill` | 32×32 | `Rect.new(8, 8, 24, 24)` |

`bar_fill` намеренно почти белый (`#E3E8E5`) — цвет ему задаёт код через
`ImageColor3`, поэтому одна картинка обслуживает и здоровье, и опыт, и полосу
босса.

## Файлы, которые лежат без дела

Двенадцать `ability_*` из первой партии: десять — формы, которых нет ни у одной
способности (`blizzard_cone`, `fire_bolt`, `holy_aura`, `ice_aura`,
`inferno_nova`, `radiant_bolt`, `shadow_chain`, `static_orbit`, `thorn_cone`,
`void_nova`), ещё два (`frost_shard`, `solar_nova`) заменены перерисованными
в цвете своей стихии — `ice_shard` и `light_burst`.

Плюс `location_frostbite_hollow`: ледяная локация, а в игре таких пока нет.

Всё это не мусор — появится способность такой формы или третья локация,
картинка уже будет.

## Как обновить id

**Главное: номер из Asset Manager — это НЕ тот номер, который нужен коду.**
Загрузка создаёт Decal, внутри которого лежит картинка со своим, совершенно
другим номером. `ImageLabel` принимает только второй; с номером декала
интерфейс молча рисует пустые квадраты. Мы уже наступили на это один раз
и переписывали все 64 числа.

1. Залить файлы в Roblox: Studio → **View → Asset Manager → Images →
   правой кнопкой → Add Images**, выделив все сразу.
2. Дождаться модерации.
3. Вписать номера декалов в `Config/Icons` — временно, чтобы скрипт ниже знал,
   что искать.
4. Выполнить в **Command Bar** — он подставит настоящие номера картинок:

```lua
local IS = game:GetService("InsertService") local Icons = require(game.ReplicatedStorage.Shared.Config.Icons) for group, tbl in Icons do if type(tbl) == "table" then for key, id in tbl do if id > 0 then local ok, m = pcall(function() return IS:LoadAsset(id) end) local d = ok and m:FindFirstChildWhichIsA("Decal", true) print(group .. "." .. key, id, d and d.Texture or "FAILED") end end end end
```

5. Из вывода взять третью колонку (`rbxassetid://<число>`) и записать эти числа
   в `Config/Icons` вместо номеров декалов.

Ключи там сверяются при загрузке с конфигами-владельцами: опечатка или забытая
новая запись роняют модуль сразу, а не оборачиваются молча не нарисованной
иконкой через месяц.
